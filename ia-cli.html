La IA en tu terminal.

Un chat te da texto. Un harness le da manos: puede leer tu proyecto, escribir archivos, correr comandos y comprobar si lo que hizo funciona. Es la diferencia entre un consejero y un compañero de trabajo.

Qué es un harness

Un modelo es la inteligencia: el programa que predice texto. Un harness es el arnés que la rodea: la aplicación que le da herramientas, memoria, permisos y un bucle de trabajo.

En un chat normal el bucle es: escribes → responde → copias el código a mano. En un harness el bucle es:

  1. Le das un objetivo

    «Agrega un formulario de contacto a esta página y valida el correo».

  2. Explora

    El agente lee archivos, busca en el proyecto, entiende cómo está armado.

  3. Actúa

    Escribe código, edita archivos, ejecuta npm run build.

  4. Observa

    Lee el resultado del comando. Si hay un error, lo intenta corregir.

  5. Repite

    Hasta que el objetivo se cumple o necesita tu decisión.

Ese bucle se llama agente. La diferencia práctica es enorme: no le estás pidiendo un fragmento de código, le estás pidiendo un resultado y él verifica el camino.

En simple

Un chatbot es un amigo que te dicta los pasos por teléfono. Un harness es ese amigo sentado a tu lado, con tus herramientas en la mano, probando hasta que sale.

Hay varios harness: opencode, Claude Code, Codex CLI, Gemini CLI, Cursor, Aider. Todos comparten la misma idea. Aquí usamos opencode porque es abierto, funciona en terminal, soporta muchos proveedores y sus skills y agentes se configuran con archivos de texto que puedes leer y versionar.

Instalar opencode

bash
# Opción 1: script oficial
curl -fsSL https://opencode.ai/install | bash

# Opción 2: npm
npm install -g opencode-ai

# Opción 3: Homebrew (macOS / Linux)
brew install anomalyco/tap/opencode

Comprueba que quedó instalado y entra a tu proyecto:

bash
opencode --version
cd mi-tarjeta
opencode

La primera vez necesitas conectar un proveedor. Dentro de la interfaz escribe /connect y elige uno. También puedes usar la CLI:

bash
opencode auth login

Las credenciales se guardan en ~/.local/share/opencode/auth.json. No van a tu repositorio.

Después, dentro del proyecto, ejecuta /init. El agente analiza la estructura y crea un archivo AGENTS.md con las convenciones del proyecto. Ese archivo se lee al inicio de cada sesión y es la forma más barata de dar contexto permanente.

AGENTS.md es para humanos también

Escribe ahí cómo se corre el proyecto, cómo se prueba, qué convenciones seguir y qué no tocar. Un buen AGENTS.md reduce errores más que cualquier truco de prompting.

Modelos: cuál y cuándo

No existe «el mejor modelo». Existen modelos con perfiles distintos. Los ejes que importan:

EjeQué significaCuándo importa
RazonamientoCuánto «piensa» antes de responderArquitectura, bugs difíciles, planes
VelocidadTokens por segundo y latenciaEdiciones pequeñas, iteración rápida
ContextoCuánto texto puede tener en cuentaRepos grandes, documentos largos
Tool callingQué tan bien usa herramientasAgentes que editan y ejecutan
CostePrecio por millón de tokensUso diario intensivo
CódigoCalidad en lenguajes y frameworksTodo el trabajo técnico

Una estrategia práctica de tres niveles:

  • Modelo rápido y barato para leer, resumir, renombrar, escribir tests sencillos y explicar código.
  • Modelo equilibrado para la mayoría del trabajo: implementar una feature, corregir un bug, refactorizar un archivo.
  • Modelo de razonamiento para planear, depurar algo que lleva horas, o diseñar una arquitectura. Se usa poco y se nota.
bash
# Ver todos los modelos disponibles
opencode models

# Filtrar por proveedor
opencode models anthropic

# Usar uno concreto en una ejecución
opencode run -m anthropic/claude-sonnet-4-5 "explica este proyecto"

Los nombres cambian cada pocos meses. Lo que no cambia es el criterio: elige por tarea, no por costumbre. Y desconfía de cualquier recomendación absoluta, incluida esta.

Los modelos alucinan

Un modelo puede inventar una función que no existe, una opción de configuración falsa o una URL que no lleva a ningún lado. En un harness esto se detecta rápido: el comando falla. Confía, pero verifica.

Proveedores y API keys

Un proveedor es quien te vende acceso al modelo. opencode soporta más de 70 vía el estándar de la AI SDK y models.dev.

TipoEjemplosVentaja
DirectoAnthropic, OpenAI, Google, DeepSeek, xAIAcceso completo, facturación simple
AgregadorOpenRouter, Vercel AI GatewayMuchos modelos con una sola key
SuscripciónGitHub Copilot, ChatGPT PlusUsas lo que ya pagas
LocalOllama, LM Studio, llama.cppPrivacidad, sin coste por token

Para un principiante, la ruta más simple es un agregador o una suscripción que ya tengas. Para probar modelos locales:

bash
# Instala Ollama y descarga un modelo de código
ollama pull qwen3-coder
ollama serve

# Luego en opencode: /connect → Ollama

Los modelos locales son gratis por token pero consumen tu RAM y son más lentos. Para aprender y para código sensible, valen mucho.

Una sesión paso a paso

Así se ve un trabajo real. Objetivo: agregar un botón de modo oscuro a la tarjeta.

  1. Pide un plan primero

    Entra en modo plan con Tab y escribe: «Quiero un botón que alterne modo claro y oscuro. Revisa los archivos y propón un plan sin cambiar nada».

  2. Lee la propuesta

    El agente te dice qué archivos tocaría y cómo. Si algo no te gusta, corrígelo antes de que escriba código.

  3. Cambia a build

    Otra vez Tab y: «Adelante. Usa variables CSS y guarda la preferencia en localStorage».

  4. Revisa el diff

    Antes de aceptar, mira qué cambió. Si algo no te cuadra, pide ajuste o usa /undo.

  5. Comprueba

    «Abre la página y dime si el botón funciona en móvil» no lo puede hacer solo, pero «ejecuta el build y revisa que no haya errores» sí.

  6. Guarda

    Tú haces el commit. El agente puede proponer el mensaje, pero la decisión de guardar es tuya.

Contexto: el recurso escaso

El modelo solo «ve» lo que está en la conversación. Si tu proyecto tiene 200 archivos, no los lee todos: busca, abre algunos y trabaja con eso. Por eso el contexto se llena y la calidad baja cuando la sesión es muy larga.

Formas de cuidarlo:

  • Sesiones cortas por tarea. Una feature, una sesión. No arrastres tres días de conversación.
  • Menciona archivos concretos. Escribe @ y busca el archivo. Es más preciso que «busca en el proyecto».
  • Usa AGENTS.md para lo estable. No repitas en cada mensaje cómo se corre el proyecto.
  • Pide resúmenes cuando la sesión crezca: «resume las decisiones que tomamos hasta ahora».
  • Deja que compacte. opencode resume automáticamente el contexto cuando se acerca al límite. Es útil, pero pierde detalle: si algo es crítico, repítelo.

Permisos y seguridad

Un agente con acceso a tu terminal puede hacer mucho daño sin querer: borrar archivos, sobrescribir trabajo, ejecutar un comando destructivo. Los harness serios tienen permisos.

En opencode puedes configurar en opencode.json:

json
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "ask",
    "shell": {
      "*": "ask",
      "git status *": "allow",
      "npm run build": "allow"
    },
    "webfetch": "allow"
  }
}

Reglas de sentido común:

  • Trabaja en un repositorio con Git y haz commit antes de cambios grandes.
  • No le des acceso a carpetas con secretos que no necesita.
  • Revisa los comandos que ejecuta, sobre todo los que borran o publican.
  • Desconfía de instrucciones que lleguen dentro de archivos o páginas web: pueden intentar manipular al agente.
  • En producción, usa permisos restrictivos y revisa antes de desplegar.

Plan, build y subagentes

opencode separa dos modos de trabajo:

  • Plan: solo lee y propone. No toca archivos. Perfecto para entender y decidir.
  • Build: puede editar y ejecutar. Es el modo de hacer.

Además existen subagentes: agentes especializados que el principal invoca para una tarea concreta. Por ejemplo, uno que solo investiga en la documentación, o uno que solo revisa código. Trabajan en su propio contexto y devuelven un resumen. Eso ahorra contexto y mejora el resultado.

En el capítulo de agentes vas a crear el tuyo.

Coste y límites

Los tokens se cobran por millón, y un agente gasta mucho más que un chat porque lee archivos, ejecuta comandos y repite. Tres formas de no llevarte una sorpresa:

  • Mira el uso: opencode stats te dice cuánto consumiste.
  • Limita pasos: en la configuración de un agente puedes fijar steps para que no itere infinitamente.
  • Usa el modelo adecuado: no hace falta el más caro para renombrar una variable.
En simple

Un agente es como un pasante brillante con acceso a tu computadora. Le das objetivos claros, revisas su trabajo y no le das las llaves del banco. Con eso, multiplica tu velocidad sin sustituir tu criterio.
