Qué es Vercel

Vercel es una plataforma que toma tu proyecto, lo construye y lo sirve en internet. Tú subes archivos; Vercel se encarga del servidor, del certificado HTTPS, de la caché global y de que la web cargue rápido desde cualquier país.

Piensa en tres capas:

  1. Tu código vive en tu computadora y en GitHub.
  2. El build convierte ese código en archivos listos para servir (HTML, CSS, JS, imágenes optimizadas).
  3. La red de Vercel guarda esos archivos en muchos lugares del mundo y los entrega desde el más cercano a quien visita.
En simple

Vercel es como una imprenta con sucursales en todo el mundo. Tú entregas el original una vez; ellos imprimen copias y las dejan en la sucursal más cercana a cada lector. Nadie espera a que el libro cruce el océano.

El plan gratuito (Hobby) es más que suficiente para aprender: proyectos ilimitados, HTTPS, deploys automáticos y dominios propios. Sus límites están pensados para uso personal, no comercial a gran escala.

Cuenta y primer deploy

  1. Crea la cuenta

    Entra a vercel.com/signup y regístrate con GitHub. Así puedes importar repositorios con un clic.

  2. Sube tu proyecto a GitHub

    Si vienes del capítulo anterior, ya está. Si no, crea un repositorio y sube al menos un index.html.

  3. Importa el proyecto

    En el panel de Vercel: Add New → Project, elige el repositorio y pulsa Deploy. Vercel detecta si es HTML puro, Next.js, Vite, Astro o cualquier otro framework.

  4. Espera el build

    Verás los logs en vivo. Cuando termina, te da una URL tipo mi-proyecto.vercel.app. Esa URL ya es pública.

Si tu proyecto es HTML, CSS y JS sin framework, no necesitas configuración: Vercel sirve la carpeta raíz. Si tienes los archivos dentro de una subcarpeta, como public/, indícalo en Root Directory.

La CLI

La interfaz web está bien para empezar, pero la terminal es más rápida y se puede automatizar. Instala la CLI:

bash
npm i -g vercel

Comprueba e inicia sesión:

bash
vercel --version
vercel login

vercel login abre el navegador o te pide tu correo. En servidores sin navegador puedes usar un token:

bash
# Crea un token en vercel.com/account/tokens
export VERCEL_TOKEN="tu_token"
vercel whoami
Los tokens son contraseñas

Un token de Vercel da acceso a tu cuenta. No lo pegues en el código, no lo subas a GitHub y no lo compartas en capturas. Si se filtra, revócalo y crea otro.

Deploy y producción

Desde la carpeta del proyecto:

bash
vercel          # deploy de preview
vercel --prod   # deploy de producción

La primera vez te hace preguntas: nombre del proyecto, equipo y carpeta. Las respuestas se guardan en .vercel/project.json, así que la próxima vez es un solo comando.

Hay dos tipos de deploy:

TipoURLPara qué
PreviewÚnica, con hashProbar cambios antes de publicarlos
ProductionLa de tu dominioLo que ve el mundo

Otros comandos útiles:

bash
vercel ls            # lista deploys
vercel inspect URL   # detalles de un deploy
vercel logs URL      # logs en vivo
vercel dev           # replica el entorno local
vercel env ls        # variables de entorno
vercel domains ls    # dominios

Git + Vercel

Cuando importas un repositorio, Vercel queda conectado. A partir de ahí:

  • Cada git push a main genera un deploy de producción.
  • Cada push a otra rama o pull request genera un deploy de preview con su propia URL.
  • Puedes ver el estado del deploy directamente en GitHub, junto al commit.
Así se trabaja en equipo

Nadie toca producción directamente. Se abre una rama, se sube, Vercel da una URL de preview, el equipo la revisa y solo entonces se mezcla a main. Es el flujo más sano y ya lo tienes gratis.

Tu dominio

Una URL algo.vercel.app funciona, pero un dominio propio se ve más serio y es más fácil de recordar. Cuesta entre 10 y 15 dólares al año, aproximadamente.

  1. Compra el dominio

    Puedes comprarlo en Vercel mismo (Domains) o en Namecheap, Cloudflare, Porkbun o cualquier registrador.

  2. Agrégalo al proyecto

    En Vercel: Settings → Domains → Add. Escribe tu dominio.

  3. Configura el DNS

    Si compraste fuera de Vercel, te dará dos registros: un A para la raíz (@) apuntando a la IP que te indique, y un CNAME para www apuntando a cname.vercel-dns.com. Cópialos en el panel de tu registrador.

  4. Espera la propagación

    Puede tardar minutos u horas. Vercel emite el certificado HTTPS solo cuando detecta que el DNS apunta bien.

Elige uno de los dos como principal (con o sin www) y redirige el otro. Tener las dos versiones sirve contenido duplicado y confunde a los buscadores.

Variables de entorno

Una variable de entorno es un valor que tu app lee al ejecutarse, pero que no está escrito en el código. Sirve para claves de API, URLs de bases de datos y configuración por ambiente.

En Vercel: Settings → Environment Variables. Cada variable se asigna a uno o más entornos: Production, Preview, Development.

En tu código, con un framework moderno, se leen así:

javascript
// En el servidor (Node, funciones, API routes)
const clave = process.env.MI_CLAVE_SECRETA;

// En el navegador, con Vite necesitas el prefijo VITE_
const url = import.meta.env.VITE_API_URL;
Lo que va al navegador no es secreto

Cualquier variable con prefijo público (VITE_, NEXT_PUBLIC_, PUBLIC_) termina dentro del JavaScript que descarga el visitante. Nunca pongas ahí una clave privada. Las claves van en el servidor y se usan desde una función.

Para desarrollo local, descarga las variables a un archivo:

bash
vercel env pull .env.local

Ese archivo va en .gitignore. Siempre.

Funciones y API

Vercel no solo sirve archivos estáticos. También ejecuta código en el servidor cuando alguien llama a una ruta. Eso te permite esconder claves, hablar con una base de datos o procesar un formulario.

Con Next.js (App Router) creas un archivo de ruta:

javascript
// app/api/saludo/route.js
export async function GET() {
  return Response.json({ mensaje: "Hola desde el servidor" });
}

Queda disponible en /api/saludo. Con HTML puro puedes usar la carpeta api/ y un archivo hola.js que exporte una función.

javascript
// api/hola.js — sin framework
export default function handler(req, res) {
  res.status(200).json({ ok: true, hora: new Date().toISOString() });
}

Estas funciones se ejecutan bajo demanda. Si nadie las llama, no consumen recursos. Es el modelo «serverless»: pagas por uso, no por un servidor encendido todo el día.

Logs, rollback y analytics

  • Logs: en el panel del deploy o con vercel logs. Ahí aparecen los console.log del servidor y los errores de ejecución.
  • Rollback: si un deploy de producción sale mal, puedes promover un deploy anterior con un clic. Vercel guarda el historial completo.
  • Analytics: métricas de visitas y rendimiento (Web Vitals) con una configuración mínima. Útil para saber si tu página es lenta de verdad.
  • Speed Insights: mide LCP, INP y CLS en usuarios reales, no en tu laptop con buena conexión.
  • Preview comments: deja comentarios sobre un deploy de preview para revisar con otras personas.

Errores típicos

«Build failed» pero en local funciona

Casi siempre es una diferencia de entorno: una variable que no existe en Vercel, una mayúscula en el nombre de un archivo (Linux distingue, macOS no) o una dependencia que instalaste localmente y no está en package.json. Lee el log del build: dice la línea exacta.

La página carga en blanco

Abre la consola del navegador. Suele ser un error de JavaScript, una ruta mal escrita o un framework que necesita un base distinto. En Vercel, revisa también que el Output Directory sea el correcto (dist, build, out…).

El dominio no conecta

Verifica los registros DNS con dig tudominio.com o en dnschecker.org. Si acabas de cambiar el DNS, espera. Y confirma que no tengas otro registro A o CNAME en conflicto.

404 en una ruta que existe

En sitios estáticos, cada URL debe corresponder a un archivo. Si usas rutas del navegador (React Router, por ejemplo), necesitas una regla de rewrite a index.html. En vercel.json: {"rewrites":[{"source":"/(.*)","destination":"/index.html"}]}.

Funciona en preview pero no en producción

Revisa que la variable de entorno exista en el entorno Production, no solo en Preview. Es el error más común y el más frustrante.

Checklist

  • El proyecto está en GitHub y Vercel está conectado.
  • Un push a main genera deploy de producción.
  • Las variables están configuradas por entorno y .env.local está ignorado.
  • El sitio tiene HTTPS (Vercel lo hace automático).
  • Probaste la URL en tu teléfono, no solo en la computadora.
  • Sabes cómo hacer rollback a un deploy anterior.
  • El README explica cómo correr el proyecto.
