Qué es una skill#

Cuando trabajas con un agente, repites las mismas instrucciones: «usa mis colores», «los nombres de archivo en kebab-case», «prueba siempre con npm test», «no uses librerías nuevas sin preguntar». Repetirlas en cada mensaje es caro y frágil.

Una skill es un paquete de instrucciones que el agente descubre y carga solo cuando la tarea lo pide. Es como un manual de procedimiento en una carpeta: no lo lees todo el día, lo abres cuando toca.

Ve dos de verdad

En el capítulo extra puedes leer completas dos skills de diseño profesionales: genjutsu e impeccable. Ver cómo están escritas enseña más que cualquier plantilla.

En simple

Es como las recetas pegadas dentro de un armario de cocina. No las llevas en el bolsillo; las usas cuando vas a cocinar ese plato. La skill vive en tu repo y el agente la consulta cuando le pides ese plato.

Anatomía de un SKILL.md#

Una skill es una carpeta con un archivo llamado exactamente SKILL.md. Empieza con un bloque de metadatos entre tres guiones (frontmatter) y luego el contenido en Markdown.

markdown
---
name: revisar-accesibilidad
description: Revisa una página antes de publicar buscando problemas de contraste, foco, etiquetas y navegación con teclado. Úsala cuando el usuario pida revisar accesibilidad o antes de un deploy.
---

## Qué hago

- Reviso el HTML en busca de imágenes sin `alt`.
- Compruebo que cada input tenga `label`.
- Verifico que los botones sean `button` o `a`, no `div`.
- Reviso el contraste de texto contra el fondo.
- Pruebo la navegación con Tab.

## Cómo lo hago

1. Abre los archivos de la página.
2. Lista los problemas encontrados con archivo y línea.
3. Propón la corrección mínima.
4. No cambies el diseño; solo lo que rompe accesibilidad.

## Formato de salida

Una tabla con: problema, archivo:línea, gravedad, arreglo.

Las reglas del frontmatter:

  • name es obligatorio. Solo minúsculas, números y guiones. Debe coincidir con el nombre de la carpeta.
  • description es obligatorio y es lo más importante: el agente lo lee para decidir si carga la skill. Debe decir qué hace y cuándo usarla.
  • license, compatibility y metadata son opcionales.

El name debe cumplir este patrón: ^[a-z0-9]+(-[a-z0-9]+)*$. Es decir: revisar-accesibilidad sí, Revisar_Accesibilidad no.

Dónde se guardan#

opencode busca skills en varias rutas:

ÁmbitoRuta
Proyecto.opencode/skills/<nombre>/SKILL.md
Global~/.config/opencode/skills/<nombre>/SKILL.md
Compatible con [CC].claude/skills/<nombre>/SKILL.md
Compatible con agentes.agents/skills/<nombre>/SKILL.md

La diferencia: las del proyecto viajan con el repositorio y las comparten quienes lo clonen. Las globales son tuyas, en cualquier proyecto. Empieza en el proyecto; cuando una skill te sirva en todo, muévela a global.

Cómo se activan#

Al iniciar, el agente ve una lista con el nombre y la descripción de cada skill. Cuando tu petición encaja con una descripción, la carga y lee el contenido completo.

Ejemplo: si tienes una skill llamada revisar-accesibilidad y escribes «revisa esta página antes de publicar», el agente debería cargarla solo. También puedes pedirlo explícitamente: «usa la skill revisar-accesibilidad».

Por eso la description es crítica. Compara:

Descripción inútil

description: Ayuda con cosas de diseño.

Descripción útil

description: Revisa contraste, foco, etiquetas y navegación con teclado en una página antes de publicar. Úsala cuando se pida revisar accesibilidad o antes de un deploy.

Tu primera skill#

Vamos a crear una skill para el proyecto de la tarjeta: que cualquier cambio respete el sistema visual.

  1. Crea la carpeta

    bash
    mkdir -p .opencode/skills/mi-sistema-visual

  2. Escribe el SKILL.md

    markdown
    ---
name: mi-sistema-visual
description: Aplica las reglas visuales de este proyecto al crear o modificar componentes. Úsala siempre que se agregue una sección, botón o tarjeta nueva.
---

## Paleta

- Fondo: `#eef0f4`
- Tinta: `#0b0f1a`
- Azul de acción: `#2337ff`
- Borde: `#c8cfdd`
- Nunca introduzcas colores nuevos sin preguntar.

## Tipografía

- Títulos: `Bricolage Grotesque`, peso 700, tracking -0.03em.
- Cuerpo: `Archivo`, 16px mínimo, line-height 1.6.
- Nunca uses más de dos familias.

## Espaciado

- Escala de 4: 4, 8, 12, 16, 24, 32, 48, 64.
- Más espacio arriba de un título que abajo.

## Componentes

- Botones con altura mínima de 44px y `border-radius: 10px`.
- Todo botón debe tener estados hover, focus y disabled.
- Las tarjetas usan borde de 1px, no sombra.

## Reglas

- Mobile first: escribe primero el estilo base y luego `@media (min-width: ...)`.
- No uses `!important`.
- No agregues dependencias externas sin preguntar.

  3. Pruébala

    Abre opencode y pide: «Agrega una sección de contacto». El agente debería cargar la skill y respetar la paleta y el espaciado.

Qué hace buena a una skill#

  • Una tarea, no un tema. «Revisar accesibilidad» es una tarea. «Diseño web» es un tema infinito.
  • Instrucciones verificables. «Usa 16px mínimo» se puede comprobar; «hazlo bonito» no.
  • El formato de salida. Si quieres una tabla, dilo. Si quieres un plan antes del código, dilo.
  • Los límites. Qué no debe hacer es tan importante como qué debe hacer.
  • Corta. Si una skill tiene 2000 líneas, el agente se pierde. Divide en varias.
  • Sin duplicar. Si algo ya está en AGENTS.md, no lo repitas aquí.

Permisos#

Puedes controlar qué skills puede usar un agente desde opencode.json:

json
{
  "permission": {
    "skill": {
      "*": "allow",
      "interno-*": "deny",
      "experimental-*": "ask"
    }
  }
}

Útil en equipos: las skills internas no se cargan en agentes que no deben verlas, y las experimentales piden confirmación.

Errores comunes#

La skill no aparece

Revisa que el archivo se llame SKILL.md en mayúsculas, que la carpeta coincida con el name, que el frontmatter tenga name y description, y que no haya otra skill con el mismo nombre.

El agente la carga cuando no debe

La descripción es demasiado amplia. Añade el contexto exacto: «Úsala solo cuando…». También puedes pedirla explícitamente por nombre en vez de esperar la activación automática.

La skill contradice al AGENTS.md

El agente recibe ambas cosas y puede confundirse. Define una jerarquía: el AGENTS.md manda en lo general, la skill en el procedimiento concreto. Si hay conflicto real, corrige uno de los dos.

Se volvió gigante

Divide por tarea. Una skill de 500 líneas es una señal de que son tres skills. También puedes mover los detalles a archivos auxiliares dentro de la misma carpeta y referenciarlos desde el SKILL.md.
