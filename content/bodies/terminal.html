Qué es una terminal

Una terminal es una ventana donde escribes órdenes y el sistema operativo las ejecuta. No hay botones: hay un prompt que espera, un comando que escribes y una salida que lees.

La misma terminal la vas a encontrar en tres sitios distintos:

DóndeCómo se veQué puedes hacer
Tu computadoraTerminal, iTerm, Windows TerminalTodo, en tu máquina
Un VPSUna sesión SSH a un servidor remotoTodo, en un servidor de internet
Termux (Android)Una app de terminalCasi todo, desde el teléfono

Los comandos son los mismos. Lo que cambia es dónde se ejecutan. Si aprendes aquí, sirve en los tres.

En simple

La terminal es como hablarle a la computadora en su idioma. La interfaz gráfica es un menú con dibujos; la terminal es decir exactamente qué quieres, con el nombre exacto de la cosa.

La anatomía de un comando

Todo comando tiene la misma forma:

estructura
comando  -opciones  argumentos

ls        -la        /var/log
│         │          │
│         │          └── sobre qué actúa
│         └───────────── cómo se comporta
└─────────────────────── qué programa ejecutar

Ejemplo real: ls -la /var/log significa «lista, en formato largo y mostrando archivos ocultos, el contenido de /var/log».

Las opciones casi siempre tienen dos formas: corta (-l) y larga (--long). Son lo mismo. Si no recuerdas una opción:

bash
ls --help
man ls        # el manual completo; se sale con q

Dónde estás: pwd, ls, cd

Antes de tocar nada, necesitas saber dónde estás. La terminal siempre está «dentro» de una carpeta.

bash
pwd                 # print working directory: la ruta completa
ls                  # lista lo que hay aquí
ls -la              # con permisos, tamaño y archivos ocultos
cd proyectos        # entra a la carpeta "proyectos"
cd ..               # sube un nivel
cd ~                # va a tu carpeta personal
cd /                # va a la raíz del sistema
cd -                # vuelve a donde estabas antes

Dos rutas que vas a ver siempre:

  • Absoluta: empieza por /. Ejemplo: /home/mara/proyectos. Funciona desde cualquier sitio.
  • Relativa: no empieza por /. Ejemplo: proyectos/web. Depende de dónde estés.

Trucos que ahorran tiempo:

  • Tab autocompleta nombres de archivo y carpeta. Úsalo siempre.
  • ↑ recupera el comando anterior. Ctrl+R busca en el historial.
  • Ctrl+C cancela lo que se está ejecutando.
  • Ctrl+L limpia la pantalla (no borra nada).
  • clear hace lo mismo que Ctrl+L.

Crear, copiar y borrar

Estos son los comandos que más vas a usar. Fíjate en que cada uno tiene su pareja: crear/borrar, copiar/mover.

bash
mkdir web               # crea la carpeta "web"
mkdir -p web/src/components  # crea toda la ruta de una vez

touch index.html        # crea un archivo vacío

cp index.html copia.html          # copia un archivo
cp -r web web-backup              # copia una carpeta entera

mv copia.html archivo.html        # renombra
mv archivo.html web/              # mueve a otra carpeta

rm archivo.html                   # borra un archivo
rm -r web-backup                  # borra una carpeta y su contenido
Cuidado con rm

rm no tiene papelera. Lo que borras, no vuelve. Nunca escribas rm -rf / ni rm -rf ~: borra el sistema entero o tu carpeta personal sin preguntar. Antes de borrar, ejecuta ls en la ruta para ver qué hay.

Ver el contenido de un archivo

Hay tres formas y cada una sirve para algo distinto:

bash
cat archivo.txt         # vuelca todo el contenido de golpe
less archivo.txt        # lo abre paginado; q para salir
head -20 archivo.txt    # las primeras 20 líneas
tail -20 archivo.txt    # las últimas 20 líneas
tail -f archivo.log     # sigue el archivo en vivo (Ctrl+C para salir)

Cuándo usar cada uno: cat para archivos cortos, less para leer algo largo, tail -f para mirar un log que se está escribiendo ahora mismo. Ese último es el que vas a usar en un servidor.

Contar y buscar dentro de archivos

bash
wc -l archivo.txt           # cuenta líneas
wc -w archivo.txt           # cuenta palabras

grep "error" app.log        # busca la palabra en el archivo
grep -i "error" app.log     # sin distinguir mayúsculas
grep -n "error" app.log     # con el número de línea
grep -r "TODO" src/         # busca en toda una carpeta
grep -c "error" app.log     # cuenta cuántas veces aparece

Combinación que vas a usar mil veces: buscar errores en un log enorme y ver solo los últimos.

bash
grep -i "error" app.log | tail -20

Esa barra vertical | se llama tubería (pipe). Toma la salida del comando de la izquierda y se la pasa al de la derecha. Es una de las ideas más potentes de Unix: programas pequeños que se encadenan.

Editar con nano

En un servidor no hay VS Code. Hay editores de terminal, y nano es el más fácil de aprender.

bash
nano archivo.txt        # abre o crea el archivo
nano /etc/nginx/nginx.conf   # abre uno del sistema (necesita sudo)

Dentro de nano, abajo verás los atajos. El ^ significa la tecla Ctrl:

AtajoQué hace
Ctrl+OGuardar (write Out). Pulsa Enter para confirmar el nombre.
Ctrl+XSalir. Si hay cambios sin guardar, te pregunta.
Ctrl+KCortar la línea actual
Ctrl+UPegar lo cortado
Ctrl+WBuscar dentro del archivo
Ctrl+\Buscar y reemplazar
Ctrl+GAyuda

La secuencia completa para editar y guardar:

  1. Abrir

    nano app.js

  2. Escribir

    Escribe o pega el contenido. El ratón no funciona; usa las flechas.

  3. Guardar

    Ctrl+O, luego Enter.

  4. Salir

    Ctrl+X.

Si nano no está instalado

En Termux: pkg install nano. En Debian/Ubuntu: sudo apt install nano. En un VPS mínimo puede que solo esté vi, que es mucho menos amable: i para escribir, Esc luego :wq para guardar y salir.

Permisos y sudo

Cada archivo tiene un dueño y unos permisos. Cuando ves Permission denied, el problema es ese.

bash
ls -l
-rw-r--r-- 1 mara mara  1024 oct 20 10:00 index.html
drwxr-xr-x 4 mara mara  4096 oct 20 09:12 src

Esas diez letras se leen así:

  • Primera: - archivo, d carpeta, l enlace.
  • Las tres siguientes: permisos del dueño.
  • Las tres siguientes: del grupo.
  • Las tres últimas: del resto.
  • r leer, w escribir, x ejecutar.

Cambiar permisos:

bash
chmod +x script.sh        # lo hace ejecutable
chmod 644 archivo.txt     # dueño lee/escribe, resto solo lee
chmod 755 carpeta         # dueño todo, resto leer y entrar

chown mara archivo.txt              # cambia el dueño
chown -R mara:mara /var/www/web     # dueño y grupo, recursivo

sudo significa «ejecuta esto como administrador». Lo necesitas para tocar cosas del sistema:

bash
sudo apt update
sudo nano /etc/hosts
sudo systemctl restart nginx
sudo no es un adorno

Un comando con sudo puede romper el sistema. Antes de ejecutarlo, lee lo que hace. Si copiaste un comando de internet y no entiendes una parte, no lo ejecutes.

Procesos y servicios

Un servidor está lleno de programas corriendo. Estos comandos te dicen qué pasa.

bash
ps aux                  # todos los procesos
ps aux | grep node      # solo los de node
top                     # monitor en vivo; q para salir
htop                    # lo mismo, más bonito (puede no estar)

df -h                   # espacio en disco
du -sh carpeta          # cuánto ocupa una carpeta
free -h                 # memoria RAM

kill 1234               # termina el proceso con PID 1234
kill -9 1234            # lo mata sin preguntar

Servicios con systemd

En un VPS, tus apps no se lanzan a mano: se registran como servicios para que arranquen solas y se reinicien si fallan.

bash
sudo systemctl status mi-app     # ¿está corriendo?
sudo systemctl start mi-app      # arrancar
sudo systemctl stop mi-app       # parar
sudo systemctl restart mi-app    # reiniciar
sudo systemctl enable mi-app     # que arranque al encender
journalctl -u mi-app -f          # sus logs en vivo

journalctl -u mi-app -f es el equivalente a tail -f pero para un servicio. Es el comando que resuelve el 80% de los «no funciona en el servidor».

Red: ssh, curl, puertos

Conectarte a un VPS:

bash
ssh root@203.0.113.42            # entrar al servidor
ssh -p 2222 root@203.0.113.42    # con otro puerto
exit                             # salir

La primera vez te pregunta si confías en la huella del servidor. Escribe yes. Si cambia sin que tú hayas reinstalado nada, desconfía.

Probar una URL o una API desde la terminal:

bash
curl https://api.github.com/users/octocat
curl -I https://tutorial-dev-es.vercel.app      # solo cabeceras
curl -X POST https://api.ejemplo.com/tareas \
  -H "Content-Type: application/json" \
  -d '{"titulo":"Comprar pan"}'

La barra invertida \ al final de una línea significa «el comando sigue abajo». Sirve para escribir comandos largos sin que se corten.

Qué está escuchando en qué puerto:

bash
ss -tulpn            # puertos abiertos y qué proceso los usa
curl localhost:3000  # probar tu app desde dentro del servidor
Por qué "funciona en local pero no fuera"

Casi siempre es una de tres: la app escucha solo en localhost en vez de 0.0.0.0; el puerto no está abierto en el firewall; o el servicio no está corriendo. Revisa en ese orden.

Tuberías y redirecciones

Esta es la parte que convierte la terminal en un taller.

bash
# guardar la salida en un archivo (sobrescribe)
ls -la > listado.txt

# añadir al final en vez de sobrescribir
echo "nueva línea" >> listado.txt

# descartar la salida de error
comando 2> errores.log

# encadenar: los archivos más grandes primero
du -sh * | sort -h | tail -5

# contar cuántas líneas tienen "error"
grep -c "error" app.log

# buscar un proceso y matarlo
ps aux | grep node | grep -v grep

Los tres flujos de cualquier programa:

  • 0 entrada estándar (stdin)
  • 1 salida estándar (stdout)
  • 2 salida de error (stderr)

Por eso 2>&1 significa «manda los errores al mismo sitio que la salida normal». Lo vas a ver en scripts y en cron.

Termux: la terminal en el bolsillo

Termux es una app de Android que te da un Linux real sin root. Sirve para practicar sin VPS.

bash
# actualizar el gestor de paquetes
pkg update && pkg upgrade -y

# lo esencial
pkg install git nodejs nano curl -y

# comprobar
node -v
git --version

Diferencias con un VPS:

TermuxVPS
PermisosSin root (salvo root real)Root con sudo
PersistenciaSe duerme si Android la cierraEncendido 24/7
AccesoDesde el teléfonoPor SSH desde cualquier sitio
Uso típicoPracticar, scripts, gitServir una web de verdad

En Termux, tu carpeta personal es /data/data/com.termux/files/home. Para llegar a las descargas del teléfono: termux-setup-storage y luego cd ~/storage/downloads.

Ejercicios

Ejercicio 01

Un taller de práctica

Crea una carpeta taller con tres subcarpetas (src, logs, tmp), un archivo notas.txt con tres líneas y un app.log con cinco líneas inventadas, dos de ellas con la palabra «error». Después lista todo, cuenta los errores con grep -c y muestra las dos últimas líneas del log.

Ejercicio 02

Editar sin miedo

Abre notas.txt con nano, añade una línea, guarda con Ctrl+O y sal con Ctrl+X. Vuelve a abrirlo para comprobar que se guardó. Después haz una copia de seguridad con cp y borra el original.

Ejercicio 03

Un pipe útil

Ejecuta ls -la /usr/bin | wc -l. ¿Qué crees que cuenta? Ahora prueba du -sh /usr/* 2>/dev/null | sort -h | tail -5 y explica qué hace cada parte de la cadena.

Ejercicio 04

Servicio propio

En un VPS, crea un archivo /etc/systemd/system/hola.service que ejecute python3 -m http.server 8000 desde /var/www. Actívalo con systemctl enable --now hola y comprueba con curl localhost:8000. Después mira sus logs con journalctl -u hola -f.

Lo único que importa

La terminal da miedo los primeros veinte minutos y después se vuelve el sitio donde de verdad trabajas. No memorices: aprende a preguntar. --help, man y una búsqueda bien escrita resuelven casi todo.
