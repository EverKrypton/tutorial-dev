Qué es React y qué problema resuelve

Con HTML y JavaScript normal, actualizar la pantalla es manual: buscas el elemento, lo modificas, recuerdas qué cambió, y si el estado se complica acabas con veinte líneas que se pisan entre sí.

React cambia el modelo: describes cómo se ve la interfaz para un estado dado y React se encarga de actualizar el DOM. No dices «borra este li y añade otro»; dices «con estas tareas, pinta esta lista».

En simple

Antes: mueves las piezas del dominó una a una. Con React: describes la figura final y el framework coloca las piezas. Tú te preocupas por los datos, no por el orden de los movimientos.

La idea central es una función: ui = f(estado). Mismo estado, misma interfaz. Cambia el estado, React vuelve a llamar a la función y actualiza solo lo que difiere.

Preparar el proyecto

La forma moderna de empezar es con Vite, que es rápido y no te esconde nada:

bash
npm create vite@latest mi-app -- --template react
cd mi-app
npm install
npm run dev

Te da http://localhost:5173. La estructura mínima:

estructura
mi-app/
├── index.html          # la única página real
├── src/
│   ├── main.jsx        # monta React en #root
│   ├── App.jsx         # tu componente raíz
│   └── index.css
└── package.json

main.jsx hace una sola cosa:

jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>

JSX: HTML con superpoderes

JSX parece HTML pero es JavaScript. Tres diferencias que confunden al principio:

HTMLJSXPor qué
class="caja"className="caja"class es palabra reservada en JS
for="campo"htmlFor="campo"Igual con for
<br><br />Todo se cierra

Y lo importante: puedes insertar JavaScript con llaves.

jsx
const nombre = "Mara";
const tareas = ["Estudiar", "Practicar"];

function App() {
  return (
    <main>
      <h1>Hola, {nombre}</h1>
      <p>Tienes {tareas.length} tareas.</p>
      <ul>
        {tareas.map((t) => (
          <li key={t}>{t}</li>
        ))}
      </ul>
    </main>
  );
}

Dos reglas que rompen el código si se ignoran:

  • Un componente devuelve un solo elemento raíz. Si necesitas dos, envuélvelos en <>...</>.
  • En una lista, cada elemento necesita una key estable. No uses el índice si la lista cambia de orden.

Componentes y props

Un componente es una función que devuelve JSX. Se escribe con mayúscula inicial, porque React distingue así entre una etiqueta HTML y tu componente.

jsx
function Tarjeta({ titulo, descripcion, hecho }) {
  return (
    <article className="tarjeta">
      <h2>{titulo}</h2>
      <p>{descripcion}</p>
      {hecho && <span>Hecho</span>}
    </article>
  );
}

export default function App() {
  return (
    <>
      <Tarjeta titulo="HTML" descripcion="Estructura" hecho />
      <Tarjeta titulo="CSS" descripcion="Estilo" hecho={false} />
    </>
  );
}

Las props son los argumentos del componente. Son de solo lectura: un componente nunca modifica las props que recibe. Si algo debe cambiar, es estado, y el estado vive en quien lo controla.

Composición antes que herencia

React no usa herencia. Si dos componentes comparten algo, extraes ese algo a un tercero y lo pasas como children o como prop. Es la misma idea que las funciones pequeñas que se combinan.

Estado con useState

El estado es lo que cambia con el tiempo. Se declara con useState, que devuelve dos cosas: el valor y la función para cambiarlo.

jsx
import { useState } from "react";

export default function Contador() {
  const [cuenta, setCuenta] = useState(0);

  return (
    <div>
      <p>{cuenta}</p>
      <button onClick={() => setCuenta(cuenta + 1)}>Sumar</button>
      <button onClick={() => setCuenta(0)}>Reiniciar</button>
    </div>
  );
}

Tres reglas del estado que cuestan horas si no las sabes:

  1. Nunca lo modifiques directamente. cuenta++ no repinta. Usa el setter.
  2. Si depende del valor anterior, usa la función: setCuenta(c => c + 1). Con clics rápidos, la versión directa pierde actualizaciones.
  3. El estado se reinicia si el componente se desmonta. Si tiene que sobrevivir, súbelo al padre o guárdalo fuera.

Un formulario controlado

jsx
function Formulario({ onCrear }) {
  const [texto, setTexto] = useState("");

  function enviar(e) {
    e.preventDefault();
    const limpio = texto.trim();
    if (!limpio) return;
    onCrear(limpio);
    setTexto("");
  }

  return (
    <form onSubmit={enviar}>
      <input
        value={texto}
        onChange={(e) => setTexto(e.target.value)}
        placeholder="Nueva tarea"
      />
      <button disabled={!texto.trim()}>Añadir</button>
    </form>
  );
}

El input está «controlado» por React: su valor viene del estado y cada tecla lo actualiza. Eso permite validar en vivo, deshabilitar el botón y limpiar el campo sin tocar el DOM a mano.

Listas y eventos

El patrón que vas a repetir siempre: array en estado, map para pintar, filter para borrar, spread para añadir.

jsx
export default function Tareas() {
  const [tareas, setTareas] = useState([
    { id: 1, titulo: "Estudiar React", hecha: false },
  ]);

  const añadir = (titulo) =>
    setTareas((t) => [...t, { id: crypto.randomUUID(), titulo, hecha: false }]);

  const alternar = (id) =>
    setTareas((t) => t.map((x) => (x.id === id ? { ...x, hecha: !x.hecha } : x)));

  const borrar = (id) => setTareas((t) => t.filter((x) => x.id !== id));

  return (
    <section>
      <Formulario onCrear={añadir} />
      <ul>
        {tareas.map((t) => (
          <li key={t.id}>
            <label>
              <input type="checkbox" checked={t.hecha} onChange={() => alternar(t.id)} />
              {t.titulo}
            </label>
            <button onClick={() => borrar(t.id)}>Borrar</button>
          </li>
        ))}
      </ul>
    </section>
  );
}

Fíjate en que nunca hacemos tareas.push(). Creamos un array nuevo. React compara por referencia: si mutas el mismo array, no ve el cambio.

useEffect: hablar con el mundo exterior

Un componente debe ser puro: mismos datos, mismo resultado. Pero a veces necesitas algo externo: leer localStorage, pedir datos a una API, suscribirte a un evento. Para eso está useEffect.

jsx
import { useEffect, useState } from "react";

export function ListaRemota() {
  const [datos, setDatos] = useState(null);
  const [error, setError] = useState(null);
  const [cargando, setCargando] = useState(true);

  useEffect(() => {
    let vivo = true;

    fetch("/api/tareas")
      .then((r) => {
        if (!r.ok) throw new Error(`Error ${r.status}`);
        return r.json();
      })
      .then((d) => vivo && setDatos(d))
      .catch((e) => vivo && setError(e.message))
      .finally(() => vivo && setCargando(false));

    return () => {
      vivo = false;
    };
  }, []);

  if (cargando) return <p>Cargando…</p>;
  if (error) return <p role="alert">{error}</p>;
  if (!datos?.length) return <p>No hay nada todavía.</p>;

  return (
    <ul>
      {datos.map((d) => (
        <li key={d.id}>{d.titulo}</li>
      ))}
    </ul>
  );
}

El array final se llama lista de dependencias y decide cuándo se vuelve a ejecutar:

DependenciasCuándo corre
[]Una vez, al montar
[id]Al montar y cada vez que cambie id
sin arrayDespués de cada render (casi nunca quieres esto)

La función que devuelves se llama cleanup: se ejecuta al desmontar o antes de la siguiente ejecución. Ahí cancelas timers, cierras conexiones o, como arriba, marcas que la petición ya no interesa.

El error clásico

Un useEffect sin array que hace setEstado provoca un bucle infinito: render → efecto → setEstado → render. Si tu pestaña se congela, mira ahí primero.

Lo que no necesita estado

Uno de los errores más comunes es guardar en estado cosas que se pueden calcular. Si un valor sale de otro, no lo dupliques.

Mal

Guardar total en estado y actualizarlo a mano en cada cambio. Tarde o temprano se desincroniza.

Bien

const total = tareas.filter(t => t.hecha).length; en el render. Siempre correcto, cero mantenimiento.

Estructurar una app pequeña

No hace falta ninguna librería de estado al principio. La regla es: el estado vive en el ancestro común más cercano de los componentes que lo usan.

estructura
src/
├── App.jsx              # dueño del estado de tareas
├── components/
│   ├── Formulario.jsx   # recibe onCrear
│   ├── Lista.jsx        # recibe tareas, onAlternar, onBorrar
│   └── Item.jsx         # recibe una tarea y sus callbacks
└── hooks/
    └── useTareas.js     # lógica reutilizable

Un hook propio es solo una función que empieza por use y llama a otros hooks:

jsx
export function useTareas() {
  const [tareas, setTareas] = useState([]);

  const añadir = (titulo) =>
    setTareas((t) => [...t, { id: crypto.randomUUID(), titulo, hecha: false }]);

  const alternar = (id) =>
    setTareas((t) => t.map((x) => (x.id === id ? { ...x, hecha: !x.hecha } : x)));

  const borrar = (id) => setTareas((t) => t.filter((x) => x.id !== id));

  return { tareas, añadir, alternar, borrar };
}

Los cinco errores que todo el mundo comete

  1. Mutar el estado

    tareas.push(x) no repinta. Crea un array nuevo con spread.

  2. Keys con el índice

    Al reordenar o borrar, React reutiliza el nodo equivocado y el input se queda con el valor de otra fila. Usa un id estable.

  3. useEffect para todo

    Si un valor se puede calcular en el render, no va en un efecto. Los efectos son para el mundo exterior.

  4. Dependencias incompletas

    Si usas una variable dentro del efecto, va en el array. El linter te avisa; hazle caso.

  5. Estado duplicado

    Dos estados que deben coincidir acaban no coincidiendo. Deriva uno del otro.

Ejercicios

Ejercicio 01

Contador con historia

Un contador con sumar, restar y reiniciar. Añade un límite: no baja de cero y no sube de diez. El botón correspondiente se deshabilita en el límite.

Ejercicio 02

Lista de tareas completa

Añadir, alternar, borrar y filtrar (todas / pendientes / hechas). Muestra un contador de pendientes calculado, no guardado en estado.

Ejercicio 03

Persistencia

Guarda las tareas en localStorage al cambiar y recupéralas al montar. Cuidado: el primer render en el servidor no tiene localStorage; piensa dónde va ese acceso.

Ejercicio 04

Consumir tu API

Conecta la lista a la API del capítulo anterior con fetch. Maneja los tres estados: cargando, error y vacío. No muestres una lista vacía mientras carga.

Lo importante

React es una forma de pensar: describes la interfaz como función del estado. Si dominas estado, props, listas y efectos, ya sabes React. El resto es ecosistema.
