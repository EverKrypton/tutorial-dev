Qué es v0 (y qué no)#

v0 es un agente de IA de Vercel especializado en construir interfaces y aplicaciones web. Le describes lo que quieres y genera código real con Next.js, React, TypeScript y Tailwind CSS. Lo ves renderizado al lado, puedes pedir cambios y, cuando te convence, lo llevas a tu repositorio o lo despliegas.

Lo que sí hace:

  • Crear pantallas completas a partir de una descripción o una captura.
  • Generar componentes con estilos coherentes.
  • Conectar formularios a una base de datos.
  • Iterar sobre el diseño con instrucciones en lenguaje natural.
  • Exportar el código a GitHub o desplegar directo.

Lo que no hace:

  • Saber qué quieres si no lo dices con precisión.
  • Reemplazar tu criterio sobre producto, contenido y accesibilidad.
  • Garantizar que el código sea el más simple o el más mantenible.
En simple

v0 es como un albañil muy rápido que nunca ha estado en tu casa. Si le dices «hazme una pared», hará una pared. Si le dices dónde, de qué material y para qué, hará la pared que necesitas.

Tu primera pantalla#

  1. Entra a v0

    Abre v0.app e inicia sesión con tu cuenta de Vercel. Hay un plan gratuito con límite de mensajes.

  2. Escribe un prompt concreto

    No «una web bonita». Mejor: «Una landing page para una cafetería de barrio llamada La Esquina. Hero con foto, tres productos con precio, horario y botón de WhatsApp. Estilo cálido, tipografía grande, mobile first.»

  3. Mira el resultado y el código

    A la derecha tienes la vista previa; puedes abrir el código y el árbol de archivos. Ahí ves qué generó y cómo.

  4. Pide cambios concretos

    «Haz el hero más alto», «cambia el botón a verde», «agrega una sección de testimonios con tres tarjetas», «en móvil el menú debe ser un botón». Cada mensaje es una iteración.

Cómo pedir bien#

v0 responde mejor cuando el prompt tiene cinco partes:

  1. Qué es: el tipo de página o componente.
  2. Para quién: la audiencia y el tono.
  3. Qué contiene: secciones, datos, acciones.
  4. Cómo se ve: estilo, colores, tipografía, referencias.
  5. Restricciones: mobile first, accesible, sin dependencias raras, en español.
Prompt vago

«Hazme una página para mi negocio»

Prompt útil

«Landing page para un estudio de fotografía de bodas en Bogotá. Hero a pantalla completa con una foto, título grande, subtítulo corto y botón "Ver portafolio". Luego una galería de 6 fotos en grid, una sección "Sobre mí" con texto breve y foto, y un formulario de contacto con nombre, correo y mensaje. Paleta crema y negro, tipografía serif elegante, mobile first, textos en español.»

Trucos que cambian el resultado

  • Adjunta una referencia. Una captura o un wireframe vale más que cien adjetivos. v0 puede imitar estructura y estilo.
  • Pide el plan antes del código. «Antes de construir, propón la estructura de secciones y el sistema de color». Revisas y luego dices «adelante».
  • Construye por partes. Primero el hero. Luego la galería. Luego el formulario. Menos errores y más control.
  • Nombra los componentes. «Crea un componente PricingCard reutilizable» produce código más limpio que «haz tres tarjetas».
  • Pide estados. «Incluye estados de carga, error y vacío» es la diferencia entre un mockup y una app.
El contexto se acumula

v0 recuerda la conversación. Si te vas por una rama equivocada, a veces es mejor empezar un chat nuevo con el prompt corregido que intentar arreglarlo con veinte mensajes. Y puedes encolar varios prompts para que se ejecuten en orden.

Iterar sin perder el rumbo#

La primera respuesta casi nunca es la buena. Y está bien: la gracia es el ciclo.

  • Corrige una cosa por mensaje. Si pides cinco cambios y dos salen mal, no sabrás cuál causó qué.
  • Sé específico con el dónde. «El botón del hero», no «el botón».
  • Usa el modo de diseño. v0 tiene un modo visual donde puedes seleccionar un elemento y pedir cambios sobre él. Es más rápido que describirlo.
  • Señala el código. Puedes comentar líneas concretas para dar contexto a tu siguiente mensaje.
  • Guarda una versión que funcione. Antes de un cambio grande, asegúrate de poder volver. v0 mantiene historial de versiones.
Mal ciclo

«No me gusta, hazlo diferente» → «sigue sin gustarme» → «otra vez»

Buen ciclo

«El hero tiene demasiado texto. Déjalo en un título de máximo 6 palabras y un subtítulo de una línea. Mantén el botón.»

El código es tuyo#

v0 genera un proyecto real. Puedes:

  • Copiar archivos y pegarlos en tu proyecto.
  • Descargar el proyecto completo.
  • Conectar GitHub y crear un repositorio con el código.
  • Desplegar en Vercel con un botón.

Eso significa que no quedas atrapado. Pero también significa que tú eres responsable de lo que hay ahí. Antes de publicar, revisa:

  • ¿Se ve bien en un teléfono real, no solo en la vista previa?
  • ¿Los textos son reales y tienen sentido?
  • ¿Los botones hacen algo o son decorativos?
  • ¿Hay imágenes con alt?
  • ¿El formulario valida y muestra errores?
  • ¿El contraste de texto es suficiente?
  • ¿Hay dependencias que no necesitas?

De v0 a producción#

El camino más corto:

  1. Pulsa Deploy en v0. Te pide conectar un proyecto de Vercel.
  2. Vercel construye y te da la URL.
  3. Si quieres seguir editando con Git, conecta el repositorio de GitHub y trabaja desde tu editor.

El camino más sano a largo plazo:

  1. Conecta GitHub desde v0 y crea el repositorio.
  2. Clónalo en tu computadora.
  3. Instala dependencias y corre en local: npm install, npm run dev.
  4. Haz cambios con tu editor y con la IA que prefieras.
  5. Push a GitHub → Vercel despliega solo.

Límites y trampas#

  • Diseño genérico. Si no das dirección, v0 tiende a un estilo limpio y parecido a todo. Tú pones el carácter.
  • Código que no entiendes. Si no sabes qué hace, no puedes mantenerlo. Pide explicaciones: «explícame este componente línea por línea».
  • Dependencias innecesarias. A veces instala una librería para algo que se resuelve en diez líneas. Pregunta si es necesaria.
  • Datos inventados. Los textos y precios son de ejemplo. Reemplázalos por los reales.
  • Límites del plan. El plan gratuito tiene cupo de mensajes. Úsalo para pensar antes de escribir.
No publiques sin revisar

Una IA puede generar un formulario que no envía nada, un enlace que va a # o una imagen de relleno. Revisa cada acción antes de decir que tu web está terminada.

Ejercicio#

Práctica

De idea a URL en 30 minutos

Elige un negocio real de tu barrio. Escribe un prompt de cinco partes, genera la landing, itera tres veces (una de contenido, una de diseño, una de móvil), exporta a GitHub y despliega en Vercel. Al final, ábrela en tu teléfono y pide a alguien que te diga qué entiende en los primeros cinco segundos. Ese feedback vale más que cualquier ajuste de sombras.
