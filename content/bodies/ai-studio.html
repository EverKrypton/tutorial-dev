Qué es Google AI Studio

Google AI Studio es la consola web de Gemini. Tiene dos partes: un playground para probar prompts y ajustar parámetros, y Build, un modo que genera una aplicación completa a partir de una descripción y la publica.

Es el equivalente de Google a v0 o a Lovable. Lo que lo hace distinto: usa Gemini, te da una API key para consumir el modelo desde tu código y las apps se pueden desplegar en Google Cloud Run.

El playground: entender el modelo antes de usarlo

Entra a aistudio.google.com, inicia sesión con tu cuenta de Google y abre el playground. Verás cuatro zonas:

  1. Sistema

    Las instrucciones permanentes: quién es el modelo y cómo debe responder. Es tu prompt de sistema.

  2. Turnos

    La conversación. Puedes escribir como usuario o como modelo para dar ejemplos de respuesta.

  3. Parámetros

    Temperatura, máximo de tokens, top-p y filtros de seguridad.

  4. Salida

    El resultado, con botón para ver el código que lo genera en Python, JavaScript, curl o la SDK.

Los parámetros, en corto

ParámetroQué haceValor sensato
TemperaturaAleatoriedad. Baja = predecible0.2 para datos, 0.9 para ideas

El botón más útil

«Get code» convierte tu prompt en código ejecutable. Es la forma más rápida de pasar de una prueba en la consola a algo que corre en tu servidor, sin adivinar el formato del cuerpo de la petición.

Build: de una idea a una app

Build es el modo de generación de apps. Le describes lo que quieres y produce una aplicación React con su lógica, su interfaz y, si hace falta, llamadas a Gemini.

Cómo pedir bien, con la misma disciplina del curso de prompting:

prompt
Construye una app para llevar el gasto de un viaje en grupo.

QUÉ HACE
- Añadir un gasto: concepto, importe, quién pagó, entre quiénes se divide.
- Ver la lista de gastos ordenada por fecha.
- Ver cuánto debe cada persona a cada otra, calculado.

CÓMO SE VE
- Mobile first. Una columna en el teléfono.
- Fondo oscuro, un solo color de acento.
- Cada gasto es una fila, no una tarjeta con sombra.

REGLAS
- Los importes se guardan en céntimos, enteros.
- Nunca dividas por cero.
- Si no hay gastos, muestra un estado vacío con un botón para añadir el primero.
- Los datos se guardan en localStorage.

NO HAGAS
- No inventes usuarios de ejemplo con nombres reales.
- No añadas login.
- No uses más de dos tipografías.

Fíjate en la estructura: qué hace, cómo se ve, reglas y prohibiciones. Es la misma anatomía de prompt del capítulo 09, aplicada a la generación de apps.

Qué hace bien y qué no

Bien

Prototipos de apps con IA, formularios, herramientas internas, demos para validar una idea con alguien en diez minutos.

Con cuidado

Lógica de negocio delicada, pagos, autenticación, cualquier cosa donde un error silencioso cueste dinero.

Usar Gemini desde tu código

La parte que de verdad te sirve como desarrollador: llamar al modelo desde tu propia app. Primero, una API key.

  1. Obtén la key

    En AI Studio, botón «Get API key» → crear en un proyecto de Google Cloud. Cópiala una vez y guárdala en un lugar seguro.

  2. Guárdala como variable de entorno

    GEMINI_API_KEY=... en .env.local, nunca en el código ni en el repositorio.

  3. Instala la SDK

    npm install @google/genai

  4. Llama al modelo

    Desde el servidor, nunca desde el navegador.

ts
// app/api/resumir/route.ts
import { GoogleGenAI } from "@google/genai";

const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY! });

export async function POST(req: Request) {
  const { texto } = await req.json();

  if (typeof texto !== "string" || texto.length < 20) {
    return Response.json({ error: "Texto demasiado corto" }, { status: 400 });
  }

  const res = await ai.models.generateContent({
    model: "gemini-2.5-flash",
    contents: texto,
    config: {
      systemInstruction: "Resume en tres viñetas, en español, sin opinar.",
      temperature: 0.2,
      maxOutputTokens: 300,
    },
  });

  return Response.json({ resumen: res.text });
}

const res = await fetch("/api/resumir", {

La key nunca va al navegador

Si pones NEXT_PUBLIC_GEMINI_API_KEY o llamas a Gemini desde un componente de cliente, cualquiera puede abrir DevTools, copiar tu key y gastar tu cuota. Siempre a través de tu API.

Salidas estructuradas

Si el resultado lo va a consumir un programa, pide JSON con esquema. Gemini lo respeta de forma mucho más fiable que pidiéndolo en prosa.

ts
const res = await ai.models.generateContent({
  model: "gemini-2.5-flash",
  contents: `Clasifica este mensaje: "${mensaje}"`,
  config: {
    responseMimeType: "application/json",
    responseSchema: {
      type: "object",
      properties: {
        categoria: { type: "string", enum: ["soporte", "ventas", "otro"] },
        urgente: { type: "boolean" },
        resumen: { type: "string" },
      },
      required: ["categoria", "urgente", "resumen"],
    },
  },
});

const dato = JSON.parse(res.text ?? "{}");

Valida siempre el JSON antes de usarlo. Un esquema reduce el riesgo, no lo elimina.

Multimodal: imágenes y audio

Una ventaja real de Gemini: el mismo modelo entiende texto, imágenes, audio y vídeo.

ts
import { readFile } from "node:fs/promises";

const imagen = await readFile("./public/factura.jpg");

const res = await ai.models.generateContent({
  model: "gemini-2.5-flash",
  contents: [
    { text: "Extrae el total y la fecha de esta factura. Devuelve JSON." },
    { inlineData: { mimeType: "image/jpeg", data: imagen.toString("base64") } },
  ],
});

Casos donde esto ahorra semanas: leer tickets y facturas, describir imágenes para accesibilidad, transcribir audio, revisar capturas de pantalla en un test.

Límites, coste y errores

  • Cuota gratuita: existe, con límites por minuto y por día. Suficiente para aprender, insuficiente para producción con tráfico.
  • Contexto: cada modelo tiene una ventana máxima. Si pegas un documento enorme, recórtalo o trocéalo.
  • Alucinaciones: sigue ocurriendo. Si el dato importa, verifícalo o dale la fuente en el prompt.
  • Errores 429: has superado la cuota. Implementa reintento con espera y un mensaje claro al usuario.
  • Errores 400: el cuerpo está mal formado o el modelo no existe. Revisa el nombre exacto.
ts
async function conReintento<T>(fn: () => Promise<T>, intentos = 3): Promise<T> {
  let ultimo: unknown;
  for (let i = 0; i < intentos; i++) {
    try {
      return await fn();
    } catch (e) {
      ultimo = e;
      await new Promise((r) => setTimeout(r, 2 ** i * 500));
    }
  }
  throw ultimo;
}

Un flujo de trabajo real

  1. Prueba en el playground

    Ajusta el prompt con datos reales hasta que la salida sea buena cinco veces seguidas.

  2. Copia el código

    «Get code» te da la llamada exacta. Adáptala a tu ruta de API.

  3. Muévelo al servidor

    La key en variable de entorno. La ruta valida la entrada y devuelve JSON.

  4. Diseña los estados

    Cargando, error, respuesta vacía. Una IA que falla sin mensaje es peor que no tener IA.

  5. Mide

    Guarda cuántas veces la respuesta sirve. Si es menos del 80%, el prompt necesita trabajo, no más modelo.

Build no reemplaza entender

AI Studio Build te da una app funcionando en minutos. Pero cuando algo falla a las dos semanas, necesitas saber qué hace el código. Genera, lee, entiende, reescribe lo que no te convenza.

Ejercicios

Ejercicio 01

Del playground al endpoint

Prueba un prompt de clasificación en el playground. Ajusta la temperatura y compara tres ejecuciones. Después llévalo a una ruta /api/clasificar con salida JSON validada.

Ejercicio 02

Una app con Build

Pide una app de notas con resumen automático. Itera tres veces: una de contenido, una de diseño, una de móvil. Después lee el código generado y localiza dónde llama al modelo.

Ejercicio 03

Imagen a datos

Sube una foto de un recibo y pide que extraiga comercio, fecha y total en JSON. Comprueba cuántas veces acierta con cinco recibos distintos.

Ejercicio 04

Los estados que nadie hace

Añade a tu app de IA: estado de carga con texto («pensando…»), error con reintento, y un aviso cuando la respuesta está vacía. Compara la sensación con la versión sin estados.

Lo importante

AI Studio es un laboratorio y un atajo, no una muleta. Lo que te hace bueno no es la herramienta: es saber qué pedir, cómo comprobar la respuesta y qué hacer cuando falla.
