Tu primera página web.

Una web son tres capas: HTML pone el esqueleto, CSS pone la ropa y JavaScript pone los músculos. Vas a construir una página real, entender cada línea y abrirla en tu teléfono.

Qué pasa cuando abres una web

Escribes una dirección, pulsas Enter y aparece una página. En medio pasan cuatro cosas:

  1. Tu computadora pregunta dónde vive ese nombre

    Un servidor DNS traduce tutorial.dev a una dirección IP, que es como el número de casa de un servidor. Es la guía telefónica de internet.

  2. Pide el archivo

    Tu navegador manda una petición HTTP: «dame la página principal». El servidor responde con el HTML, el CSS, las imágenes y el JavaScript.

  3. El navegador lo arma

    Lee el HTML, construye un árbol de elementos (el DOM), aplica el CSS y ejecuta el JavaScript. Todo eso pasa en milisegundos.

  4. Pinta la pantalla

    Calcula posiciones, tamaños y colores, y dibuja. Si algo cambia después, vuelve a calcular solo la parte necesaria.

En simple

Una web es como pedir comida: tú llamas al restaurante (DNS), pides un plato (HTTP), la cocina lo prepara (servidor) y el repartidor te lo lleva (el navegador). Tú solo ves la comida servida.

Lo importante: tu página no «vive» en internet por arte de magia. Es un conjunto de archivos que alguien tiene que subir a un servidor. Eso es lo que harás en el capítulo de Vercel.

HTML: el esqueleto

HTML son etiquetas que dicen qué es cada cosa: esto es un título, esto es un párrafo, esto es un enlace, esto es una imagen. No dice cómo se ve; dice qué significa.

html
<!-- La receta mínima de cualquier página -->
<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi primera página</title>
</head>
<body>
  <h1>Hola, mundo</h1>
  <p>Esta página existe y es mía.</p>
</body>
</html>

Qué hace cada línea:

  • <!doctype html>: le dice al navegador «esto es HTML moderno».
  • <html lang="es">: el idioma. Ayuda a lectores de pantalla y traductores.
  • <head>: información que no se ve. Título de la pestaña, codificación, enlaces a CSS.
  • <meta name="viewport">: sin esta línea, el móvil finge tener 980px de ancho y todo se ve diminuto. Es la base del mobile first.
  • <body>: todo lo que sí se ve.

Las etiquetas que vas a usar siempre

EtiquetaSignificadoÚsala para
<h1>…<h6>Encabezados por nivelUn solo h1 por página
<p>PárrafoTexto normal
<a href="...">EnlaceIr a otra página o sección

No uses etiquetas por su aspecto

No elijas <h3> porque «se ve más pequeño». Los niveles son jerarquía, no tamaño. Si quieres otro tamaño, cámbialo con CSS. Y no uses <div> para un botón: usa <button>, que ya funciona con teclado.

CSS: la ropa

CSS son reglas. Cada regla elige elementos y les asigna propiedades:

css
/* selector { propiedad: valor; } */
body {
  background: #eef0f4;
  color: #0b0f1a;
  font-family: system-ui, sans-serif;
  line-height: 1.6;
}

h1 {
  font-size: clamp(2rem, 8vw, 3.5rem);
}

Hay tres formas de seleccionar:

  • h1 elige todas las etiquetas h1.
  • .tarjeta elige todos los elementos con class="tarjeta".
  • #inicio elige el elemento con id="inicio". Úsalo poco; las clases se reutilizan mejor.

El modelo de caja

Todo elemento es una caja con cuatro capas: contenido, padding (relleno interior), border (borde) y margin (espacio exterior). Si no entiendes por qué algo se ve enorme, casi siempre es el padding o el margin.

css
*, *::before, *::after {
  box-sizing: border-box; /* el ancho incluye padding y borde */
}

.tarjeta {
  width: 100%;
  max-width: 420px;
  padding: 24px;
  border: 1px solid #c8cfdd;
  border-radius: 14px;
  margin: 24px auto;
}

box-sizing: border-box es la primera línea de CSS que deberías escribir en cualquier proyecto. Evita que un width: 100% con padding se desborde.

Cajas, flex y grid

Para colocar cosas, hoy bastan dos herramientas:

  • Flexbox: para una fila o una columna. Ideal para barras, botones, listas horizontales.
  • Grid: para dos dimensiones. Ideal para una galería o el layout de una página.
css
/* Una fila que se adapta */
.fila {
  display: flex;
  flex-wrap: wrap;
  gap: 12px;
  align-items: center;
}

/* Una rejilla que cambia de 1 a 3 columnas sola */
.rejilla {
  display: grid;
  gap: 16px;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
}

Esa última línea es oro: «repite columnas de mínimo 220px y reparte el espacio». En un teléfono cabe una; en una laptop, tres. Sin media queries.

Mobile first de verdad

Mobile first no es «hacer la versión de escritorio y apretarla». Es diseñar primero para la pantalla más pequeña y añadir complejidad cuando hay espacio.

css
/* Estilos base: teléfono */
.hero {
  padding: 32px 20px;
  font-size: 1rem;
}

/* A partir de 720px, añadimos */
@media (min-width: 720px) {
  .hero {
    padding: 72px 40px;
    font-size: 1.15rem;
  }
}

Las reglas de oro del móvil:

  • Área táctil mínima de 44×44 px en botones y enlaces importantes.
  • Texto base de al menos 16 px. Menos, y el navegador hace zoom al enfocar un campo.
  • Nada de scroll horizontal. Si aparece, busca un width fijo o una imagen sin max-width: 100%.
  • Líneas de texto de 45–75 caracteres. En móvil, párrafos cortos.
  • Contraste real: texto normal mínimo 4.5:1 contra el fondo.
  • No escondas acciones importantes solo en :hover: en un teléfono no existe el hover.

JavaScript: los músculos

HTML y CSS son estáticos. JavaScript permite reaccionar: un clic, un formulario, un dato que llega. No necesitas saberlo todo para empezar; necesitas tres ideas: seleccionar, escuchar y cambiar.

javascript
// 1. Seleccionar un elemento del HTML
const boton = document.querySelector("[data-tema]");

// 2. Escuchar un evento
boton.addEventListener("click", () => {
  // 3. Cambiar algo
  document.body.classList.toggle("oscuro");
});

Para que funcione, el HTML necesita un botón con ese atributo y el CSS una clase .oscuro:

html
<button type="button" data-tema>Cambiar tema</button>
css
body.oscuro {
  background: #0b0f1a;
  color: #f0f3fa;
}

data-tema es un atributo personalizado. No significa nada para el navegador, pero te sirve como gancho en JavaScript y en CSS. Es una convención muy útil: úsala en lugar de inventar ids por todas partes.

El orden importa

Si tu JavaScript está en el <head>, agrega defer o pon el script al final del body. Si no, intentará seleccionar un botón que todavía no existe y fallará con null.

Accesibilidad mínima

Accesibilidad no es un extra para «usuarios especiales». Es que tu página funcione con teclado, con lector de pantalla, con poca luz y con mala conexión. Estas seis cosas cubren el 80%:

  • Un h1 por página y niveles de encabezado en orden.
  • Texto alternativo en imágenes: alt="Descripción". Si es decorativa, alt="".
  • Todo lo que se pueda pulsar debe ser <button> o <a>, no un div con onclick.
  • <label for="..."> en cada campo de formulario.
  • Foco visible: no borres el outline sin reemplazarlo por algo claro.
  • Contraste suficiente y nada de texto dentro de una imagen.

Proyecto: tu tarjeta

Vas a construir una página de presentación de una sola pantalla. Crea una carpeta llamada mi-tarjeta con dos archivos: index.html y styles.css.

index.html

html
<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mara López — Diseño web</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <main class="tarjeta">
    <p class="saludo">Hola, soy</p>
    <h1>Mara López</h1>
    <p class="bio">
      Hago páginas simples para negocios pequeños.
      Estoy aprendiendo en público y este es mi primer proyecto.
    </p>
    <ul class="enlaces">
      <li><a href="mailto:hola@ejemplo.com">Escríbeme</a></li>
      <li><a href="https://github.com/">GitHub</a></li>
    </ul>
    <button type="button" class="tema" data-tema>Modo oscuro</button>
  </main>
  <script src="app.js"></script>
</body>
</html>

styles.css

app.js

javascript
const boton = document.querySelector("[data-tema]");

boton.addEventListener("click", () => {
  document.body.classList.toggle("oscuro");
  boton.textContent = document.body.classList.contains("oscuro")
    ? "Modo claro"
    : "Modo oscuro";
});

Abre index.html con doble clic. Ya tienes una página. Cambia el nombre, los colores y el texto. Ese es el ejercicio real: hazla tuya.

DevTools

Las herramientas del navegador son tu taller. Se abren con F12 o clic derecho → «Inspeccionar». Lo que más vas a usar:

PestañaPara qué
ElementsVer y editar el HTML y el CSS en vivo. Nada se guarda; es un laboratorio.
ConsoleVer errores y ejecutar JavaScript. Tu console.log aparece aquí.
NetworkVer qué archivos carga la página y cuánto pesan.
Device toolbarSimular un teléfono. Icono de móvil arriba a la izquierda.
LighthouseUn informe de rendimiento, accesibilidad y SEO. Útil, pero no es una nota final.
En simple

DevTools es como abrir el capó del auto mientras el motor está andando. Puedes tocar y ver qué pasa sin romper nada. Es la forma más rápida de aprender CSS: cambia un valor y mira.

Qué sigue

Ya tienes archivos. Ahora necesitas dos cosas: guardar versiones para no perderlas y subirlas a algún lugar para que el mundo las vea. Eso son Git y Vercel.

Antes de seguir, comprueba:

  • La página se ve bien a 360 px de ancho.
  • No hay scroll horizontal.
  • El botón de tema funciona y se puede pulsar con Tab + Enter.
  • El texto se lee sin hacer zoom.
