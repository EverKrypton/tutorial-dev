Web#

HTML
El lenguaje que describe la estructura y el significado del contenido: títulos, párrafos, enlaces, imágenes.
CSS
El lenguaje que controla la apariencia: colores, tipografía, espaciado, disposición.
JavaScript
El lenguaje que da comportamiento: reaccionar a clics, validar formularios, pedir datos.
DOM
El árbol de elementos que el navegador construye a partir del HTML. JavaScript lo lee y lo modifica.
Responsive
Que la página se adapta al ancho de la pantalla. Se hace con unidades relativas, flex, grid y media queries.
Mobile first
Diseñar primero para la pantalla pequeña y ampliar después. No es lo mismo que «hacerlo responsive».
Breakpoint
El ancho a partir del cual cambia el diseño, definido con @media (min-width: ...).
Viewport
El área visible del navegador. La etiqueta meta viewport es la que hace que el móvil no finja tener 980px.
Accesibilidad (a11y)
Que la página funcione con teclado, lectores de pantalla y contraste suficiente. Beneficia a todos.
Semántica
Usar la etiqueta que describe el contenido (button, nav, main) en lugar de un div genérico.
DevTools
Las herramientas del navegador para inspeccionar HTML, CSS, red y errores. Se abren con F12.
HTTPS
HTTP cifrado. Vercel lo configura automáticamente con un certificado.
DNS
El sistema que traduce un dominio a una dirección IP. Los registros A y CNAME son los que conectan tu dominio.
CDN
Una red de servidores distribuidos que entrega tus archivos desde el lugar más cercano al visitante.
API
Una forma de que dos programas se hablen. Casi siempre: mandas una petición y recibes datos, normalmente en JSON.
JSON
Un formato de texto para datos con estructura de listas y pares clave-valor. El idioma común de las APIs.
Frontend
Lo que corre en el navegador: HTML, CSS, JavaScript, interfaces.
Backend
Lo que corre en el servidor: base de datos, autenticación, lógica privada.
Framework
Un conjunto de herramientas y convenciones para construir. Next.js, Astro, Vite o SvelteKit son ejemplos.

Git y GitHub#

Repositorio
Una carpeta vigilada por Git, con todo su historial dentro de .git.
Commit
Una foto del proyecto en un momento, con un mensaje que explica el cambio.
Staging
El área donde preparas qué cambios entran en el próximo commit.
Rama (branch)
Una línea de trabajo paralela. main suele ser la principal.
Merge
Unir los cambios de una rama con otra.
Conflicto
Cuando dos ramas cambiaron la misma línea. Git te pide que decidas.
Remoto
Una copia del repositorio en otro lugar, normalmente GitHub. Se llama origin por convención.
Clone
Copiar un repositorio remoto a tu computadora.
Push / Pull
Subir tus commits al remoto / traer los del remoto a tu copia.
Pull request
Una propuesta de cambios para revisar antes de mezclarlos.
Fork
Una copia de un repositorio ajeno en tu cuenta, para modificarlo sin afectar el original.
.gitignore
Lista de archivos que Git debe ignorar: dependencias, entornos, archivos generados.
README
El archivo que explica qué es el proyecto y cómo usarlo. Es la portada del repositorio.

Vercel#

Deploy
El proceso de construir tu proyecto y publicarlo. Cada deploy tiene su propia URL.
Preview
Un deploy de prueba con URL única. Se genera por cada push a una rama o pull request.
Producción
El deploy que ve el mundo, servido en tu dominio.
Build
La fase en la que se instalan dependencias y se generan los archivos finales.
Root Directory
La carpeta del repositorio donde Vercel debe buscar el proyecto.
Output Directory
La carpeta que el build genera y Vercel sirve: dist, build, out…
Variable de entorno
Un valor de configuración que no está en el código: claves, URLs, credenciales.
Función serverless
Código que se ejecuta en el servidor solo cuando alguien lo llama.
Edge
Ejecución en servidores cercanos al usuario, con baja latencia y capacidades limitadas.
Rollback
Volver a un deploy anterior cuando el nuevo sale mal.
Rewrite / Redirect
Servir otra ruta sin cambiar la URL / mandar al navegador a otra URL.
Web Vitals
Métricas de experiencia real: LCP (carga), INP (respuesta), CLS (estabilidad visual).

IA y modelos#

LLM
Modelo grande de lenguaje. Predice texto y, con entrenamiento, aprende a seguir instrucciones y usar herramientas.
Token
Un fragmento de texto (parte de una palabra). Los modelos cuentan y cobran por tokens.
Contexto
Todo el texto que el modelo tiene delante en una interacción: instrucciones, historial, archivos.
Ventana de contexto
El máximo de tokens que cabe. Al superarlo, se recorta o se resume.
Prompt
La entrada que le das al modelo: instrucción, contexto, datos y formato.
Prompt de sistema
Las instrucciones base que definen el comportamiento del modelo en toda la conversación.
Temperatura
Control de aleatoriedad. Baja: respuestas predecibles. Alta: más variadas y creativas.
Alucinación
Cuando el modelo inventa algo con seguridad. No es mentira: es un patrón plausible sin base.
Few-shot
Dar ejemplos dentro del prompt para que el modelo imite el patrón.
Chain of thought
Pedir al modelo que razone por pasos antes de responder. Mejora tareas complejas.
RAG
Recuperar documentos relevantes y ponerlos en el contexto para que el modelo responda con esa información.
Embedding
Una representación numérica del significado de un texto. Sirve para buscar por similitud.
Fine-tuning
Reentrenar un modelo con ejemplos propios para especializarlo. Distinto de dar contexto en el prompt.
Inferencia
El acto de que el modelo genere una respuesta. Cada llamada es una inferencia.
Multimodal
Modelo que entiende más de un tipo de entrada: texto, imágenes, audio.

Agentes#

Harness
La aplicación que rodea al modelo y le da herramientas, permisos y un bucle de trabajo. opencode es uno.
Agente
Un modelo con un objetivo, herramientas y la capacidad de actuar en varios pasos.
Tool calling
La capacidad del modelo de pedir que se ejecute una función: leer un archivo, buscar, llamar una API.
Skill
Un paquete de instrucciones reutilizables que el agente carga solo cuando la tarea lo requiere.
Subagente
Un agente especializado que el principal invoca para una tarea, con su propio contexto.
MCP
Model Context Protocol: un estándar para conectar herramientas y datos externos a un agente.
Inyección de prompt
Cuando un texto externo intenta convertirse en instrucción y manipular al agente.
Permisos
Reglas que deciden qué puede hacer el agente solo, qué requiere confirmación y qué está prohibido.
AGENTS.md
El archivo donde describes el proyecto y sus convenciones para que el agente lo lea siempre.
Orquestación
Coordinar varios agentes o pasos para resolver una tarea compleja.

Chuletas de comandos#

Git

bash
git init                        # iniciar repositorio
git status                      # ver qué cambió
git add .                       # preparar todo
git commit -m "mensaje"         # guardar foto
git log --oneline               # historial corto
git switch -c rama              # crear y cambiar de rama
git switch main                 # volver a main
git merge rama                  # traer cambios
git pull                        # bajar del remoto
git push                        # subir al remoto
git restore archivo             # descartar cambios
git stash                       # apartar cambios
git stash pop                   # recuperarlos
git clone URL                   # copiar un repo

Vercel

bash
npm i -g vercel                 # instalar CLI
vercel login                    # iniciar sesión
vercel                          # deploy de preview
vercel --prod                   # deploy de producción
vercel dev                      # entorno local
vercel ls                       # listar deploys
vercel logs URL                 # logs
vercel env ls                   # variables
vercel env pull .env.local      # bajarlas
vercel domains ls               # dominios
vercel inspect URL              # detalles

opencode

bash
opencode                        # abrir la interfaz
opencode run "..."              # ejecutar sin interfaz
opencode -c                     # continuar sesión
opencode models                 # ver modelos
opencode auth login             # conectar proveedor
opencode agent create           # crear agente
opencode mcp add                # añadir MCP
opencode stats                  # uso y coste
opencode upgrade                # actualizar
