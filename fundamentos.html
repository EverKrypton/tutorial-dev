Cómo piensa un programa.

Antes de escribir una página necesitas entender qué es una instrucción, cómo se guarda un dato y por qué un programa se rompe. Aquí no hay magia: hay piezas pequeñas que encajan.

Qué es programar

Programar es escribir una lista de instrucciones que otra cosa pueda ejecutar sin que tú estés mirando. Ese «otra cosa» puede ser el navegador, un servidor, tu teléfono o un robot. La computadora no es lista: es obediente. Hace exactamente lo que le dices, incluso cuando lo que le dijiste no era lo que querías.

En simple

Imagina que le dictas a alguien cómo preparar un sándwich, pero esa persona nunca ha visto uno. No puede «deducir» que hay que abrir el pan. Si no lo dices, no pasa. Programar es partir una tarea en pasos tan pequeños que no quede nada por adivinar.

Un programa tiene tres momentos, siempre:

  1. Entrada: los datos que recibe. Lo que escribe el usuario, un archivo, la respuesta de otra máquina.
  2. Proceso: lo que hace con esos datos. Sumar, comparar, ordenar, transformar.
  3. Salida: el resultado. Un texto en pantalla, un archivo guardado, un correo enviado.

Cuando algo no funciona, casi siempre puedes encontrar el problema preguntándote en cuál de los tres momentos se rompió: ¿llegó mal el dato, lo procesé mal o lo mostré mal?

La anatomía de un programa

Los lenguajes cambian de ropa, pero casi todos tienen las mismas cinco piezas. Si aprendes qué hace cada una, cambiar de lenguaje es aprender vocabulario nuevo, no empezar de cero.

PiezaPara qué sirveAnalogía
VariablesGuardar un dato con un nombreCajas etiquetadas
CondicionesElegir un caminoUn cruce con señales
BuclesRepetir algoUna cinta de correr
FuncionesAgrupar pasos reutilizablesUna receta con nombre
Datos compuestosGuardar muchos valores juntosUna lista o una ficha

Vamos a verlas en JavaScript porque es el lenguaje que entiende el navegador. No te preocupes por la sintaxis todavía: mira la idea.

Variables y tipos

Una variable es un nombre que apunta a un valor. Sirve para no repetir el mismo dato por todo el código y para poder cambiarlo después.

javascript
// Una caja llamada "nombre" que guarda un texto
let nombre = "Mara";

// Una caja llamada "edad" que guarda un número
const edad = 24;

// Un valor de sí o no
let tieneCuenta = true;

// Si mañana cambia, podemos reemplazarlo
nombre = "Mara López";

Hay dos palabras para crear variables y la diferencia importa:

  • const significa «esto no va a cambiar de valor». Úsala por defecto. Te avisa cuando algo se sale de lo previsto.
  • let significa «esto puede cambiar». Úsala solo cuando de verdad necesites reasignar.
  • var es una reliquia. Puedes ignorarla mientras aprendes.

Los tipos que vas a usar el 95% del tiempo

TipoEjemploQué es
string"hola"Texto. Siempre entre comillas.
number42, 3.14Números. Sin comillas.
booleantrue, falseVerdadero o falso. Solo esos dos.
array["pan", "leche"]Una lista ordenada.

Ojo con las comillas

"42" es texto; 42 es número. Si sumas "4" + 2 JavaScript devuelve "42" (pega textos), no 6. Ese es uno de los bugs más comunes del mundo.

Tomar decisiones

Un programa necesita bifurcaciones: si pasa esto, haz aquello; si no, haz lo otro. Eso es un if.

javascript
const temperatura = 31;

if (temperatura > 30) {
  console.log("Hace calor. Lleva agua.");
} else if (temperatura > 18) {
  console.log("Se está bien.");
} else {
  console.log("Abrígate.");
}

Las condiciones se construyen con comparadores:

OperadorPregunta
===¿Es exactamente igual? (usa tres, no dos)
!==¿Es distinto?
> <¿Es mayor / menor?
>= <=¿Es mayor o igual / menor o igual?
&&Y. Se tienen que cumplir las dos.
||O. Basta con que se cumpla una.
En simple

Un if es un portero. Si traes la invitación, pasas; si no, te manda a la fila de al lado. El portero no adivina: solo evalúa la condición que le diste.

Repetir sin morir

Si quieres mostrar los números del 1 al 5, no escribes cinco líneas: usas un bucle. El más común es for.

javascript
for (let i = 1; i <= 5; i++) {
  console.log("Vuelta número " + i);
}

Se lee así: empieza en 1; mientras sea menor o igual a 5; después de cada vuelta, súmale 1. Hay tres piezas separadas por punto y coma: inicio, condición y paso.

Para recorrer una lista existe una forma más legible:

javascript
const compras = ["pan", "leche", "café"];

for (const producto of compras) {
  console.log("Falta comprar: " + producto);
}
El bug clásico

Si la condición del bucle nunca se vuelve falsa, el programa se cuelga. Eso es un bucle infinito. Siempre pregúntate: «¿qué hace que esto termine?».

Funciones

Una función es un bloque de pasos con nombre. Le das datos (parámetros), hace su trabajo y devuelve un resultado. Sirve para no repetir y para ponerle nombre a una idea.

javascript
function saludar(nombre) {
  return "Hola, " + nombre + ". ¿Cómo estás?";
}

const mensaje = saludar("Mara");
console.log(mensaje); // "Hola, Mara. ¿Cómo estás?"

Fíjate en return: no imprime nada, devuelve un valor para que quien llamó a la función lo use. Es la diferencia entre cocinar y entregar el plato.

Una función debería hacer una sola cosa y hacerla bien. Si tienes que usar la palabra «y» para describirla («valida el formulario y envía el correo y muestra el éxito»), probablemente son tres funciones.

Listas y objetos

Una lista (array) guarda varios valores en orden. Un objeto guarda valores con nombre. Juntos pueden representar casi cualquier cosa.

javascript
const tarea = {
  titulo: "Publicar mi web",
  hecha: false,
  etiquetas: ["vercel", "principiante"]
};

console.log(tarea.titulo);      // "Publicar mi web"
console.log(tarea.etiquetas[0]); // "vercel"

Cuando estos datos viajan entre tu página y un servidor, se escriben en un formato de texto llamado JSON. Es casi idéntico a un objeto de JavaScript, pero con las claves entre comillas. Lo vas a ver en todas las APIs.

Errores y debugging

Un error no significa que no sirvas para esto. Significa que la computadora encontró una instrucción que no puede ejecutar o un resultado que no esperaba. Los errores son información, no castigos.

Hay tres familias:

  • De sintaxis: escribiste algo mal. Falta un paréntesis, una coma, una comilla. El programa ni siquiera arranca.
  • De ejecución: arrancó, pero se rompió a mitad de camino. Por ejemplo, intentaste leer una propiedad de algo que no existe.
  • De lógica: no se rompe, pero hace otra cosa. El código corre y el resultado está mal. Los más difíciles.

La rutina de debugging

  1. Lee el error completo

    No solo la primera línea. La última suele decir qué pasó; las anteriores, dónde. Busca el nombre del archivo y el número de línea.

  2. Reproduce el problema

    Encuentra la acción mínima que lo provoca. «A veces falla» no es un bug reproducible; «falla cuando el campo está vacío» sí.

  3. Haz visible lo invisible

    Imprime los valores con console.log justo antes del punto donde crees que se rompe. Compara lo que esperabas con lo que hay.

  4. Aísla

    Comenta partes, divide el problema, reduce el caso. Si quitas la mitad y sigue fallando, ya sabes en qué mitad está.

  5. Corrige una cosa a la vez

    Si cambias cinco cosas y funciona, no aprendiste cuál era el problema. Cambia una, prueba, repite.

El pato de goma

Explícale el problema en voz alta a un objeto inanimado. Al ordenar la explicación, tu cerebro encuentra el hueco. Funciona tan bien que parece una broma.

Pensar como programador

La habilidad más valiosa no es memorizar sintaxis: es descomponer. Estos cuatro movimientos sirven para cualquier proyecto, en cualquier lenguaje.

1

Descomponer

«Hacer una web» es demasiado grande. «Mostrar un título», «listar tres tarjetas», «publicar el archivo». Parte hasta que cada pieza quepa en una sesión.

2

Reconocer patrones

Si ya hiciste un formulario, el siguiente es el mismo patrón con otros campos. No empiezas de cero: adaptas.

3

Abstraer

Quédate con lo importante y esconde el detalle. Una función enviarCorreo() oculta veinte pasos; tú solo ves la intención.

4

Escribir el algoritmo

Antes de código, escribe los pasos en español. Si no puedes explicarlo en cinco líneas, todavía no lo entiendes.

Nombres que no den vergüenza

Un buen nombre ahorra un comentario. Compara:

Mal

const x = 86400;

Bien

const SEGUNDOS_POR_DIA = 86400;

Usa inglés o español, pero sé consistente. No mezcles getUser con obtenerProducto en el mismo archivo. Y no le pongas comentarios que repiten lo que el código ya dice: explica el porqué, no el qué.

Ejercicios

No necesitas instalar nada. Abre la consola del navegador (F12 → Consola) y prueba. Equivocarte ahí no rompe nada.

Ejercicio 01

La receta

Escribe en español los pasos para preparar tu bebida favorita. Luego marca cuáles son entrada, proceso y salida. ¿Dónde hay una decisión? ¿Dónde hay una repetición?

Ejercicio 02

Conversor de temperatura

Crea una función celsiusAFahrenheit(grados) que devuelva el resultado de grados * 9 / 5 + 32. Pruébala con 0, 25 y 100.

Ejercicio 03

Lista de compras

Declara un array con cinco productos. Recórrelo e imprime cada uno con su número: «1. pan», «2. leche»… Pista: necesitas un contador o el índice del bucle.

Ejercicio 04

FizzBuzz

Imprime los números del 1 al 30. Si es divisible entre 3, imprime «Fizz»; si es divisible entre 5, «Buzz»; si es divisible entre ambos, «FizzBuzz». Es el ejercicio clásico de entrevista y entrena condiciones y bucles a la vez.

Ejercicio 05

Rompe algo a propósito

Toma el código de las funciones y quita una comilla, cambia un === por =, usa una variable que no existe. Lee cada error. Aprender a leer errores es la mitad del oficio.

Lo único que importa

No necesitas saber matemáticas avanzadas para hacer páginas web. Necesitas paciencia para dividir problemas y costumbre de comprobar lo que crees. Eso es todo.
